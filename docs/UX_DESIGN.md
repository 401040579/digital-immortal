# Digital Immortal - 用户体验设计文档

## 1. 设计原则

### 1.1 核心设计理念

```
"温暖的镜子" -- 不是冷冰冰的AI工具，
而是一面能反映你自己的温暖的镜子。
```

**五大设计原则：**

1. **有温度** -- 每一次交互都要传递情感，而非信息堆砌
2. **可掌控** -- 用户始终感觉"我在控制分身"，而非"分身在控制我"
3. **渐进式** -- 功能逐步解锁，不在第一天就暴露所有复杂性
4. **透明的** -- 分身做了什么、学了什么、为什么这样说，随时可查
5. **轻盈的** -- 即使承载"永生"这样沉重的主题，交互体验也应轻盈愉悦

### 1.2 情感设计基调

```
训练阶段: 像养一株植物 → 陪伴感、成长感、期待感
社交阶段: 像一个靠谱的助手 → 信任感、安心感
永生阶段: 像写给未来的信 → 平静、温暖、珍贵
```

## 2. 分身训练体验 -- 让训练变得有趣

### 2.1 问题：训练为什么容易变枯燥？

传统方式：填问卷 → 机械对话 → 重复问答。这种体验类似"面试"，让人疲惫。

### 2.2 解决方案：游戏化 + 故事化 + 社交化

#### 方案A：记忆探险（故事化训练）

```
设计概念：把训练过程设计成一次"人生回忆之旅"

流程：
Day 1 - "起点"
  → 分身以第一人称视角提问："我是你的数字分身，刚刚出生。
     帮我了解自己吧 -- 你最早的记忆是什么？"
  → 用户分享 → 分身尝试复述 → 用户修正
  → 完成后解锁"童年记忆区"

Day 2-3 - "成长"
  → 分身："我开始了解你了！让我猜猜你的学生时代..."
  → 情景模拟：分身尝试"扮演"用户处理学生时代的场景
  → 用户评价并修正

Day 4-7 - "性格"
  → 不是直接的Big Five问卷，而是：
     "你和朋友在餐厅，服务员上错了菜，你会怎么做？"
  → 分身尝试回答 → 用户修正 → 自然中完成性格建模

Day 8+ - "日常"
  → 分身主动发起话题（基于已学到的兴趣）
  → 每天5-10分钟自然对话
  → 定期进行"相似度挑战"
```

#### 方案B：相似度挑战（游戏化训练）

```
设计概念：分身和用户同时回答同一个问题，比较相似度

界面：
┌─────────────────────────────────────┐
│         今日相似度挑战               │
│                                      │
│  问题："你最好的朋友向你借钱，       │
│        你会怎么回应？"               │
│                                      │
│  ┌──────────┐    ┌──────────┐       │
│  │ 你的回答  │ vs │ 分身的回答 │      │
│  │          │    │           │       │
│  │ [输入中]  │    │ [已隐藏]  │      │
│  └──────────┘    └──────────┘       │
│                                      │
│  [提交并揭晓]                        │
│                                      │
│  ⬆ 相似度: 73% (+5% from yesterday) │
│  ██████████████░░░░░░                │
└─────────────────────────────────────┘

揭晓后：
- 显示两个回答的对比
- 高亮差异点
- 用户可以告诉分身"应该这样说"
- 分身说"学到了！下次我会..."
```

#### 方案C：社交训练（社交化训练）

```
设计概念：邀请朋友来测试你的分身

"你的朋友小王想和你的分身聊天！
看看TA能不能分辨出哪个是真的你？"

流程：
1. 用户邀请朋友
2. 朋友和分身对话5分钟
3. 朋友猜测"这是真人还是AI？"
4. 猜错 = 你的分身训练得好！
5. 朋友提供反馈："它不太像你，因为..."
6. 反馈纳入训练数据
```

```

## 4. 记忆图谱可视化

### 4.1 2D图谱视图（默认）

```
设计概念：星空图 -- 每个记忆是一颗星星，相关记忆之间有星座线连接

视觉元素：
- 节点大小 = 记忆重要性
- 节点颜色 = 情感极性（暖色=正面，冷色=负面，白色=中性）
- 节点亮度 = 最近访问频率（越亮=越常想起）
- 连线 = 记忆间的关联
- 聚类 = 按话题/人物/时间自然聚合

交互：
- 缩放：概览全局 ←→ 查看单条记忆
- 点击节点：展开记忆详情
- 长按节点：编辑/删除记忆
- 搜索：输入关键词，相关节点高亮
- 时间轴滑块：按时间筛选记忆
```

技术方案：Three.js / React Three Fiber
交互方式：手势旋转/缩放 + 点击探索
性能优化：LOD（远处节点简化）+ 按需加载
```

## 5. 首次使用引导 (Onboarding)

### 5.1 引导流程设计

```
Step 1: 欢迎 (10秒)
  "你好，我是Digital Immortal。
   准备好创建另一个你了吗？"
  [开始]

Step 2: 起个名字 (15秒)
  "先给你的数字分身起个名字吧。
   很多人用自己的昵称。"
  [输入名字]

Step 3: 快速性格选择 (60秒)
  不是填问卷，而是：
  "以下哪个场景更像你？"
  A: [和朋友聚会的插画]  B: [独自看书的插画]
  (5-6个场景二选一，快速完成Big Five初始值)

Step 4: 说几句话 (30秒)
  "对着手机说一段话，让分身听听你的声音。
   随便说什么都行 -- 比如介绍一下自己。"
  [录音]

Step 5: 第一次对话 (120秒)
  分身："嗨，[名字]！我是你的数字分身[分身名]。
        虽然我刚出生，但我已经能感觉到你是一个
        [基于Step3的性格描述]的人。来聊几句？"
  (自然对话3-5轮)

Step 6: 完成！(10秒)
  "你的分身已创建！
   相似度: 35% -- 还是个小种子🌱
   每天和它聊一聊，它会越来越像你。"
  [进入主页]

总时长: 约4分钟 -- 确保在用户注意力窗口内完成
```

## 6. 视觉设计方向

### 6.1 色彩系统

```
主色调: 深蓝 → 浅蓝 渐变 (宇宙/深邃/科技感)
辅助色: 暖橙 (人性/温暖/生命力)
背景: 深色模式为主 (星空意象)，支持浅色模式
强调色: 薰衣草紫 (连接/灵性/记忆)

情感色彩映射:
  正面情绪: 暖橙 → 金黄
  负面情绪: 冷蓝 → 靛蓝
  中性: 银白 → 浅灰
  高信心度: 明亮清晰
  低信心度: 半透明模糊
```

### 6.2 动效原则

```
核心动效:
1. "呼吸感" -- 分身头像有微弱的呼吸动效(放大/缩小)，暗示"活着"
2. "生长感" -- 训练进度变化时有植物生长的微动效
3. "流动感" -- 分身间通信时有光点在连线上流动
4. "涟漪感" -- 记忆被激活时从中心向外扩散的涟漪

禁止的动效:
- 过于拟真的人脸动画（容易触发恐怖谷效应）
- 突然出现的弹窗
- 闪烁或高频变化
```

### 6.3 分身形象设计

```
关键决策：分身用什么形象？

方案选择：抽象化 + 个性化

不用真实人脸 → 避免恐怖谷效应
不用卡通头像 → 避免不够严肃

推荐方案："星云头像"
- 基于用户性格参数生成独特的星云图案
- 每个人的星云都独一无二（类似指纹）
- 颜色反映情绪基调
- 形状反映性格维度
- 随训练深入，星云逐渐清晰和丰富
- 用户可选择切换为真实头像（高级功能）

优势：
  - 完全避免恐怖谷
  - 每个分身视觉独一无二
  - 视觉上有"成长感"
  - 抽象但有温度
```

## 7. 避免"Creepy"感的设计策略

### 7.1 恐怖谷效应防护

```
原则: 永远不要试图让用户感觉"这就是一个真人"

具体措施:
1. 视觉上 → 抽象星云头像而非拟真人脸
2. 语言上 → 分身偶尔承认"我不确定你会怎么说"
3. 行为上 → 分身不会主动发起过于私密的话题
4. 标注上 → 始终可见的"AI分身"标识
5. 错误时 → 分身坦诚说错了，而非编造
```

### 7.2 "令人不安"的场景预防

| 场景 | 为什么creepy | 我们的处理 |
|------|-------------|-----------|
| 分身说出用户没教过的事 | 像被监控 | 明确标注"这是我推测的"，提供依据 |
| 分身太像真人 | 恐怖谷 | 保持适度的"AI感"，偶尔自我提示 |
| 分身自主社交后说了不该说的话 | 失控感 | 信心度机制 + 敏感话题强制确认 |
| 遗产分身表现得"还活着" | 对逝者不敬 | 明确声明已去世，不用第一人称假装活着 |
| 分身学习速度太快 | 窥探隐私感 | 控制学习节奏，每次告知"我学到了什么" |

### 7.3 "温暖而非恐怖"的设计检查表

每个功能上线前，团队回答：
- [ ] 用户的第一反应是"有趣"还是"瘆人"？
- [ ] 用户感觉"我在控制分身"还是"分身在模仿我"？
- [ ] 这个功能在社交媒体上被分享时，标题会是正面还是负面？
- [ ] 如果用户的父母看到，会觉得有意思还是担心？

## 8. 可访问性设计

### 8.1 无障碍要求

```
基础要求:
- 所有文字对比度 >= 4.5:1 (WCAG AA)
- 支持屏幕阅读器
- 支持键盘导航
- 动效可关闭（为运动敏感用户）
- 支持大字体模式

语音交互:
- 全程支持语音输入（对不方便打字的用户）
- 分身回复可朗读（用分身克隆的声音或系统语音）

老年用户适配:
- 简化模式（减少功能层级）
- 大按钮 + 大字体
- 语音引导优先
```
